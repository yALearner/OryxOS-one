```markdown
# OryxOS 项目上下文

## 项目定位
OryxOS 是用 Java 21 + Spring Boot 3.5 实现的面向企业场景的 Agent OS（Agent 统一底座）。
装在企业自己的 K8s 或服务器上，作为统一底座运行多个业务 Agent，共享渠道接入、模型路由、
工具调用、记忆系统、沙箱执行能力。数据完全留在企业自己的基础设施，不锁任何云生态。
Agent 在 OryxOS 上是**配置出来的，不是写代码写出来的**。

## 当前阶段
**核心阶段（pre-alpha）第 1~2 周**：核心能力一（001-provider）、核心能力二（002-react）、
CLI 与 Session 持久化（003-cli）均已交付并人工验收（PR #1 af0fe10、PR #2 836e740 已合并；
003-cli 分支待合并 PR #3）。
新序列 spec-kit 流程（`/oryx-spec <编号>` + `docs/requirements/NNN-slug.md` 六段式需求文档）已稳定：
001-provider、002-react（28 任务）、003-cli（29 任务）全绿交付；人工验收方法论沉淀于
`.claude/skills/oryx-spec/references/manual-acceptance.md`，每课 review 指南在 `docs/reviews/NNN-review.md`。
下一节按课件分节推进：第 19 节 Notify、第 20 节 Tool 体系（ToolRegistry + 内置 HttpTools +
各工具 execute 首行接 Sandbox.enforce，**就位后补跑 Demo 一完整版**）、第 21/22 节 Memory、
第 23/24 节 Sandbox 实现、第 25 节 Scheduler、第 26 节 Web。

## 9 个 Maven 模块（✅ = 已有交付内容）

| 模块 | 职责 |
|------|------|
| `oryxos-core` ✅ | 引擎本体已交付：ReActLoop、PromptBuilder、ToolExecutor、AgentService、ProfileContext、ContextLoader、Session、SessionManager、LlmGateway（依赖倒置端口）、ToolSchemaAdapter（自 provider 迁入）；抽象：OryxTool、Profile/ProfileLoader/ProfileRegistry、Message、ToolResult、JsonSchema |
| `oryxos-provider` ✅ | ProviderService（implements LlmGateway）、ProviderConfiguration（显式映射 Map<name, ChatModel>）、ProviderProperties、ProviderNotFoundException |
| `oryxos-memory` | MemoryService 统一门面，LongTermMemory 可插拔后端（待第 21/22 节） |
| `oryxos-tool` ✅ | Sandbox 接口墙已交付（Sandbox/SandboxAction/ActionType/SandboxViolationException）；内置 Tool、ToolRegistry 待第 20 节 |
| `oryxos-channel-cli` ✅ | CliChannel（读—转交—打印交互循环；终端编码跟随 console charset） |
| `oryxos-web` | REST API（10 个端点）、GlobalExceptionHandler、OpenAPI（待第 26 节） |
| `oryxos-storage` ✅ | LlmCall/ToolInvocation/SessionEntity + 三个 Repository；手工 schema.sql（llm_calls + tool_invocations + sessions 三张表，ddl-auto: none；spring.sql.init.mode=always 启动执行） |
| `oryxos-cli` ✅ | Picocli 入口 OryxOsCli 挂 12 子命令（4 分组父 + 12 叶命令）、CliAgentConfiguration（重命令装配）、轻命令零 Spring 秒回 |
| `oryxos-boot` ✅ | OryxOsApplication（scanBasePackages="com.oryxos" + **@EnableJpaRepositories/@EntityScan("com.oryxos.storage")**——坑九）；打包 mainClass=com.oryxos.cli.OryxOsCli（单二进制唯一入口，cli 插件 repackage skip） |

**依赖方向**：storage 被 core 与能力层依赖；provider/memory/tool 依赖 core（core 不反向依赖，
跨模块消费走 core 定义的端口接口——LlmGateway 先例）；web/channel-cli 依赖所有能力层；
cli 组装所有模块；boot 做依赖聚合。

## 关键设计决策（不可违背，宪法 9 条）

1. **ReAct Loop 自实现**：不用 Spring AI 的 Agent 抽象，自己写核心循环
2. **Spring AI 只用两件事**：LLM Provider 协议转换 + @Tool JSON Schema 生成。
   禁用自动 tool 执行（`ToolCallingChatOptions.internalToolExecutionEnabled(false)`，
   调度完全由 ReActLoop + ToolExecutor 控制；代码禁用 ChatClient）
3. **Provider 显式映射**：Map<String, ChatModel>，不靠类型扫描；core 消费能力层一律走 core 定义的
   端口接口（LlmGateway 先例：签名与 ProviderService.chat 逐字一致，装配时以实例注入）
4. **一个目录 = 一个 Agent**：.oryxos/agents/<name>/AGENT.md（frontmatter + 正文）；
   Skill 以软连接绑定、渐进式披露，frontmatter 不声明 skills:
5. **审计 Day One**：tool_invocations + llm_calls 两张表从核心阶段就写入 SQLite
6. **同步执行模型**：全程同步阻塞 + Java 21 Virtual Thread，不引入 Reactor/WebFlux
7. **不用 SecurityManager**：Sandbox 接口先行（enforce(SandboxAction)），
   核心阶段 WhitelistSandbox 三层白名单
8. **三种触发源共用一个引擎**：CLI/Web/Scheduler → AgentService.process() → ReActLoop
9. **Tool 模块三合一**：内置 Tool + MCP Client + Sandbox + NotifyTools 合并在 oryxos-tool
```

```
## 编码约定
- 所有代码用 Java 21，充分利用 Virtual Thread
- 模块间通过接口解耦，新增 Channel/Tool 只加新模块不改 core
- 敏感配置（API key）走环境变量 ${VAR_NAME}，不明文写 YAML
- 日志用 Logback 结构化 JSON（MDC session_id + kv 字段）；**日志参数不带用户可控值**
  （sessionId/工具名等——FindSecBugs CRLF_INJECTION_LOGS 门禁会拦，关联信息在审计表）
- 遵循 CLAUDE.md 与 .specify/memory/constitution.md 的 9 条宪法原则
- 构建：先按"实施环境"export 后再 `mvn clean package`；SQLite 测试库用 `:memory:` + pool=1
- 实施顺序以 tasks.md 的 [P] 并行标记与阶段依赖为准，每个用户故事完成后跑其 Independent Test
- 编译门禁含 Error Prone `-Werror`：`LocalDateTime.now()` 要显式时区、`split(regex)` 要 `-1` 参数、
  `toLowerCase()` 要 `Locale.ROOT`、字节转 String 要显式 UTF_8
- 手工建表（schema.sql）是唯一真相源（ddl-auto: none）——新表 DDL 增量追加，测试执行同一份脚本；
  建表脚本由 boot 启动接线（spring.sql.init.mode=always + classpath:schema.sql，SQLite 不被视为
  embedded 必须显式 always）
- 人工验收用「临时 harness」模式（真装配 + 真落库 + 真模型，@Tag("integration")），不进交付物、
  验收后删除；方法见 `.claude/skills/oryx-spec/references/manual-acceptance.md`
- CLI 实跑经验：终端输入编码跟随 `console().charset()`（硬编码 UTF-8 会把 GBK 终端读乱）；
  打包唯一入口 = oryxos-boot（mainClass=OryxOsCli，cli 模块 repackage skip 防嵌套 fat jar）；
  重命令 `web(NONE)` 不起 Tomcat；Windows 下 jar 被瞬时锁时等待数秒重试打包
```
